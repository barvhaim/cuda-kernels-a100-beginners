# תרגילים

## תרגיל 1: אינדוקס

שנו את `01_vector_add` ל-1000 איברים ו-128 threads/block. הדפיסו את מספר ה-blocks והסבירו למה הופעלו יותר מ-1000 threads.

## תרגיל 2: בכוונה בלי guard

צרו עותק מקומי של vector add, הסירו את `if (i < n)` והריצו רק דרך `compute-sanitizer`. אל תשמרו את הגרסה השבורה. תעדו מה הכלי מצא.

## תרגיל 3: SAXPY

שנו את `alpha` ואת ערכי הקלט. עדכנו את expected value וודאו שהבדיקה נכשלת לפני העדכון ועוברת אחריו.

## תרגיל 4: Reduction

שנו את הקלט לערכים `2.0f`. ה-kernel הנוכחי דורש `threads` שהוא חזקה של 2. אל תשנו ל-96 או ל-192: לולאת חציית ה-offset תאבד ערכים. אחר כך החליפו את סיום ה-CPU ב-launches חוזרים של אותו kernel, עם `threads=256`, עד שנשאר סכום יחיד. בכל launch חשבו מחדש את מספר ה-blocks לפי מספר הסכומים החלקיים הנוכחי.

## תרגיל 5: Matmul

נסו `TILE=8`, `16`, `32`. ודאו נכונות ומדדו. אל תניחו שהגרסה עם tile הגדול ביותר תהיה המהירה ביותר.

## תרגיל 6: ניסוי A100

הריצו Nsight Compute על vector add ועל matmul. כתבו לכל אחד השערה: memory-bound או compute-bound, והביאו שני metrics שתומכים בה.

## יומן התקדמות

לכל תרגיל רשמו:

- הפקודה שהרצתם.
- התוצאה הצפויה והאמיתית.
- metric אחד אם מדדתם ביצועים.
- כשל אחד שראיתם ומה גרם לו.
- דבר אחד שאתם מסוגלים להסביר עכשיו בלי להסתכל בקוד.
