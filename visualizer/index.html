    THE MODEL PATH

    Inside one LLM token

    An LLM is not one giant CUDA kernel. It is a pipeline of tensor operations. These teaching kernels reveal the CUDA pattern underneath each part.

    01Token embeddingtoken ID → hidden vectorrow lookup + 2D indexing → 02Q / K / V + MLPhidden vector → projected featuresmatrix multiplication → 03Attention softmaxscores → probabilitiesmax + sum reductions → 04 · LIVE ABOVEResidual streamlayer output + previous hidden stateparallel vector add → 05RMSNormhidden vector → normalized vectorshared-memory reduction → 06Logitshidden vector → vocabulary scoresLM-head projection
    Elementwise CUDA

    Residual Add and SiLU give independent threads hidden dimensions to update.

    Reduction CUDA

    RMSNorm and softmax make threads cooperate to compute statistics.

    Matrix CUDA

    Q/K/V, MLP, and LM-head projections are dominated by matrix multiplication.

    Teaching view: production LLM engines commonly fuse operations and use cuBLAS, CUTLASS, Tensor Cores, and FlashAttention-style kernels.
